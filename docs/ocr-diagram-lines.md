# スキャンした図の線を文章にする

GURI で 2026-09 に入れた読み取りを、別のアプリへ移すための説明です。相続関係図やフロー図のように、箱の文字と、箱を結ぶ線の両方が意味を持つページが対象です。

視覚モデルは矢印を見ています。落ちるのは画素が消えたあとと、「文字だけを書き、説明は書くな」という指示のあとです。文字の書き起こしはそのままにして、線だけを決まった行にします。続柄の判断はさせません。

## 画像をどう送るか

1 ページにつき 1 回送ります。思考は切ります。ページごとに推論させると、長いスキャンが遅くなります。出力は決まった行への書き起こしです。

スキャン PDF は、幅 1700px、JPEG 品質 0.92 で描いてから送ります。0.85 は細い線を消しました。0.85 を選んだ理由は線の再現ではなく、1 ページをリクエストに収めることでした。GURI の本文上限は 12MB で、0.92 でも 1 ページは収まります。利用者が付けた画像ファイルは、再圧縮しません。

文字が何も無いページは、空の文字列で返させます。謝罪や説明を本文にしないためです。

## 視覚モデルに渡す指示

次の文字列を、画像と一緒に渡します。要約させず、読めない字は「□」にします。

```
この画像は日本の法律文書を紙で読み取ったものです。書かれている文字をそのまま書き出してください。
要約・翻訳・言い換えをしません。読めない文字は「□」にします。
段落と改行は元の見た目に合わせます。罫線だけの表は行ごとにタブ区切りで書きます。表は図にしません。
箱や文字が線や矢印で結ばれているときは、本文のあとに「〔図〕」と1行置き、結ばれている相手を1行ずつ書きます。箱の中の文字は日付も含めて残します。端点は箱の文字を短くせずそのまま書きます。
向きのある矢印は「山田太郎 → 山田花子」です。線のそばに文字があるときは「山田太郎 -子→ 山田花子」とします。矢印が無く一重の線は「山田太郎 — 山田花子」、二重の線は「山田太郎 ═ 山田花子」、点線は「山田太郎 ┄ 山田花子」です。並びは図の位置のまま（上または左を先）にします。
親子、婚姻、養子とは書きません。上下の配置から矢印に変えません。二重線を婚姻とは呼びません。図が無いページでは「〔図〕」を書きません。紙に印刷された「図1」などの見出しは本文の文字として残します。
文字が何も無ければ、何も書かずに空で返してください。感想や説明は書きません。
```

同じページに本文と図があるときは、本文が先で、`〔図〕` があとです。紙に印刷された「図1」は本文の文字として残します。アプリが足した区切りは `〔図〕` です。

線の種類は次のとおりです。

- 矢印は `→` です。そばに文字があるときは `山田太郎 -子→ 山田花子` です。
- 矢印の無い一重線は `—` です。二重線は `═` です。点線は `┄` です。
- 1 本の線を 1 行にします。先に書く名前は、図の上にある箱、または左にある箱です。
- 端点は箱の中の文字を短くしません。日付も箱の文字として残します。

親子、婚姻、養子とは書かせません。上下に並んでいることから矢印へ変えることもさせません。二重線を婚姻とは呼ばせません。線のそばに「子」と印刷されていれば、その文字だけが残ります。

区切りを裸の「図」にすると、資料の「図1」と区別できません。`---` は、添付の区切りに使うアプリとぶつかります。`〔図〕` は、項番号を `〔1.〕` のように足すアプリと同じ鉤括弧です。そのアプリが行頭の `〔〕` を番号として消すなら、消えない印に変えてください。印を変えたら、下の説明も同じ語にします。

指示を 2 か所に置くアプリでは、2 つの文字列をテストで一致させます。コメントに「同じ文」と書くだけでは、片側だけが古くなります。

## あとで読むモデルへの説明

書き起こしを別のモデルが読むなら、資料があるときだけ次を伝えます。

```
「〔図〕」以下の「→」「—」「═」「┄」は、画像の線を書き起こしたものです。線のそばに文字が無ければ続柄は補っていません。「〔図〕」は Word の項番号ではなく、開いている文書の引用にも使いません。
```

数字や固有名詞と同じく、読み違えがありえます。`〔図〕` の行を、開いている文書に元からある文としては検索しません。

## このやり方では届かないもの

次は、指示文を変えても画像がモデルに届きません。

- 各ページの文字が空白と改行を除いて 200 字以下のときだけ、PDF 全体を画像読み取りにします。1 ページでも 201 字あれば、ファイル全体を文字のままにします。図だけのページが後ろにあっても、そのページだけは画像になりません。文字レイヤーは箱の名前だけを残し、線を残しません。
- Word や docx に貼った図は読みません。テキスト抽出は図形を捨てます。スキャンを画像として貼っただけの docx も、視覚モデルには回りません。
- 複数ページにまたがる 1 つの図はつなぎません。ページとページの間は空行です。
- 長い資料は先頭から残します。末尾のページの図は、本文と同じ切れ方で落ちます。
- すでに読み取った添付は、付け直すまで新しい指示では読み直しません。

罫線だけの表は図にしません。今までどおり、行ごとのタブ区切りです。

## テストで分かること

単体テストが見るのは、指示文に `〔図〕`、`→`、`┄`、端点を短くしないこと、続柄を足さないこと、表はタブのままであること、図が無いページでは `〔図〕` を書かないこと、空のページは空のままであること、です。視覚モデルが実際にその行を返すかは、ページ画像とモデルが無いテストでは分かりません。
