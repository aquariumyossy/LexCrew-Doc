# LexCrew Doc

Word デスクトップの作業ウィンドウから、別 PC の **MTPLX**（OpenAI 互換、既定モデル `qwen3.8-flash-next`）、**SearXNG**、同一 PC の **Argos** 索引を使って、法律文書の点検・起案・調査をチャットで行うアドインです。指示は自然言語ひとつで、本文の書き換え・コメント・書式変更は LLM の `tool_calls` として実行され、文書への変更はすべて Word の変更履歴に残ります。

出力は下書き・点検用であり、法律意見ではありません。LLM が書いた判例・条文番号は **未確認** です。Word に「出典」として入れるのは SearXNG のヒット（タイトル・URL）と Argos のヒット（タイトル・ファイルパス）だけです。

対象は **横書きの .docx** と **Word デスクトップ**（WordApi 1.4、概ね 2022年8月以降の Microsoft 365）です。Word on the web、`.doc`、保護ビュー、読み取り専用、縦書きは対象外です。

## 構成

```
Word デスクトップ  →  作業ウィンドウ (HTTPS)
                         │  same-origin /api/*
                         ▼
                   Tauri 常駐（127.0.0.1:28765）
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
   MTPLX（別 PC・LAN）  SearXNG      Argos（同一 PC
                                    127.0.0.1:17890）
```

- タスクペインから MTPLX へは直接叩きません（CORS と API キー漏洩を避けるため）。Argos も作業ウィンドウから直接は叩かず、サイドカーが `127.0.0.1:17890` へ中継します（`localhost` は IPv6 だけに解決されることがあるため使いません）。
- サイドカーは **Word を開く PC** で動かします。MTPLX 機に Word 用サーバは置きません。
- Windows ではトレイ常駐（NSIS インストーラ）が使えます。開発時の作業ウィンドウ live reload はこれまでどおり `npm start` です。
- フォルダは、作業ウィンドウと開発用サーバが `src/`、配布する常駐が `src-tauri/`（KURU の `outlook/` と `server.release.ts` に相当）、手渡しが `scripts/` と `release/` です。
- Base URL、API キー、SearXNG の URL は `%APPDATA%\LexCrew\connection.json` が正です。LexCrew Mail と同じファイルです。モデル、タイムアウト、フォント、思考、Argos は作業ウィンドウの `localStorage` に残します。文書には埋め込みません。
- 会話履歴は Word PC の `%APPDATA%\GURI\history.db`（SQLite）だけに置きます。本番は Tauri の `rusqlite`、開発用 Express は `better-sqlite3` で、同じファイルと同じ API 契約を使います。
- 文書本文・プロンプト・思考（`reasoning_content`）はログに出しません。

## 必要なもの

| 役割              | 置く場所                   | ソフトウェア                                                                                                  |
| ----------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Word + 本アドイン | Word を開く PC（Windows）  | Microsoft 365 の Word デスクトップ。利用者はインストーラのみ。開発時は Node.js 18 以上と Rust（stable）+ MSVC |
| LLM               | 別 PC 可（多くの場合 Mac） | [MTPLX](https://github.com/mtplx) `mtplx serve`                                                               |
| ウェブ検索        | 同じ LAN でも別 PC でも可  | SearXNG（`search.formats` に `json`）                                                                         |
| ローカル索引      | Word と同じ PC             | Argos（起動中は LAN 共有がオフでも `http://127.0.0.1:17890`）                                                 |

このリポジトリに表・罫線・余白、OOXML 出力、ログイン、クラウド LLM は含みません。選択範囲の文字と段落の書式は `format_text` と `format_paragraph` で付けられます。

利用者の PC に Node.js / Electron は不要です。Word が入っていれば WebView2 は通常すでに入っています。

## 旧 Electron 版からの移行（必ず先に）

旧 Electron 版も、いまの常駐も、ポート 28765 とインストール先の名前 **GURI** を使います。Tauri 版を入れる前に Electron 版を外してください。スタートメニューの旧ショートカットも残ります。

1. トレイに残っていれば終了します。
2. 「アプリと機能」から旧 GURI（Electron）をアンインストールします。
3. 残っていれば削除します。
   - `%LOCALAPPDATA%\Programs\GURI`
   - スタートメニュー / デスクトップの旧ショートカット
   - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` の `GURI`（値が `--autostart` を含まないもの）
   - `HKCU\Software\GURI`
4. `%APPDATA%\GURI` のログはそのままで構いません。証明書ディレクトリは Tauri 版が作り直します。

PowerShell でのレジストリ削除例:

```powershell
Remove-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name "GURI" -ErrorAction SilentlyContinue
Remove-Item -Path "HKCU:\Software\GURI" -Recurse -ErrorAction SilentlyContinue
```

## Word PC でのセットアップ

### インストーラ（Windows・推奨）

cmd は不要です。リポジトリで `npm run package` すると `release\LexCrew-Doc-Setup-<version>.exe` ができます。`src-tauri\target\release\bundle\nsis\` はビルドの作業場所です。目安は数十 MB です。インストール先は `%LOCALAPPDATA%\GURI`、実行ファイルは `GURI.exe` のままです。

1. **先に旧 Electron 版をアンインストール**します（上の手順）。
2. インストーラを実行します（ユーザー領域。管理者の昇格は出ません。Node.js は不要です）。アプリと機能の表示名は **LexCrew Doc** です。
3. スタートメニュー画面で、フォルダ名の既定は **LexCrew Doc** です。「ショートカットを作成しない」にするとスタートメニューには作りません。入れ替え時は古い `GURI` フォルダのショートカットを消します。
4. 完了画面で「デスクトップショートカットを作成する」は既定オンです。外すとデスクトップに `LexCrew Doc.lnk` はできません。「LexCrew Doc を実行」も既定オンです。外すとその場では起動しません。
5. ログイン時の起動はセットアップ成功時に有効です。完了画面の実行とは別です。トレイの「ログイン時に起動」で外せます。入れ直すと再びオンになります。スタートアップの一覧名は `GURI` のままです。
6. 起動すると、コンソールも Word も開かずトレイに常駐します。完了画面で実行を外し、スタートメニューも作らなかったときは、デスクトップのショートカットか、次のログオンで起動します。
7. 初回起動で localhost 用 HTTPS 証明書を **現在のユーザー** の信頼ストアへ入れます（`certutil -user`。管理者は不要です）。作業ウィンドウが白紙なら、LexCrew Doc を終了してから Word を開き直してください。
8. Word で横書きの `.docx` を開き、ホームタブの **LexCrew** で作業ウィンドウを出します。

トレイを終了すると作業ウィンドウは API に届きません。リボンのボタンは残ることがあります。アンインストール時にアドイン登録とログイン時起動は外します。

ポート 28765 を旧 GURI や `npm start` が掴んでいると起動できません。メッセージに従って先に終了してください。

**Windows ファイアウォール**

- インバウンド: 本アドインは `127.0.0.1` のみ待受なので、Word PC 側で 28765 を LAN に開ける必要はありません。
- アウトバウンド: Word PC から **MTPLX 機のポート（既定 8000）** と **SearXNG のポート** へ届くようにします。届かない場合は作業ウィンドウに、ファイアウォールと `0.0.0.0` 待受の確認を出します。Argos は同じ PC のループバックだけを使います。
- LLM PC 側では、8000 番への **インバウンド** を Word PC の LAN から許可します。

### 開発者向け（npm）

作業ウィンドウの live reload は webpack + Express です。トレイ・証明書・本番 HTTPS は Tauri（Rust）です。両方を同時に起動すると 28765 が衝突します。

ビルドには [Rust stable](https://rustup.rs/) と Windows の MSVC ビルドツールが必要です。

1. [Node.js LTS](https://nodejs.org/) と Rust を入れます。
2. このリポジトリをクローンし、依存関係を入れます。

```bash
npm install
```

3. 開発用 HTTPS 証明書を一度だけ入れます（`office-addin-dev-certs`）。管理者権限が必要です。

```bash
npx office-addin-dev-certs install
```

Windows で証明書を信頼しないと、作業ウィンドウが白紙のままになります。インストール後、Word とブラウザを開き直してください。

4. 起動します。HTTPS タスクペインと開発用サイドカーが同じプロセスで立ち上がり、Word へサイドロードされます。

```bash
npm start
```

サーバだけ起動する場合（この環境でのプレビューや、すでにマニフェストを読み込んでいるとき）:

```bash
npm run dev-server
```

トレイ常駐をソースから試す場合（作業ウィンドウ用の `dist/` も作ります）:

```bash
npm run tauri dev
```

待受は `https://127.0.0.1:28765` です。マニフェストの SourceLocation は証明書に合わせて `https://localhost:28765/taskpane.html` です。`localhost` が IPv6 (`::1`) にだけ解決して繋がらないときは、OS の hosts で `127.0.0.1 localhost` を優先するか、Word を開き直してください。

止めるとき（`npm start` でサイドロードした場合）:

```bash
npm stop
```

### 手動サイドロード

`npm start` が Word を自動で開かない場合:

- **Windows:** ファイル → オプション → セキュリティ センター → 信頼済みアドイン カタログ、または [Sideload Office Add-ins](https://learn.microsoft.com/office/dev/add-ins/testing/sideload-office-add-ins-for-testing) の手順で `manifest.xml` を指定します。トレイ常駐の本番では、起動時に WEF Developer へ自動登録します。
- **Mac:** `~/Library/Containers/com.microsoft.Word/Data/Documents/wef/` に `manifest.xml` を置き、Word を再起動してホームタブの **LexCrew** を押します。Mac 向けトレイ常駐は未提供です。

対象ファイルは横書きの `.docx` を編集モードで開いてください。

## MTPLX（LLM PC）

OpenAI 互換の `/v1/chat/completions` と `/v1/models` を出します。クラウド LLM は使いません。

LAN に出す典型例（キー無しの `0.0.0.0` 待受は MTPLX 側で拒否されます）:

```bash
mtplx serve --host 0.0.0.0 --api-key-file ~/.mtplx/api-key
```

- 既定ポートは 8000 です。作業ウィンドウの Base URL 例: `http://192.168.1.10:8000/v1`
- 既定モデルは `qwen3.8-flash-next` です。接続確認で `/v1/models` の ID を列挙し、表記ゆれは手入力できます。`/v1/models` が取れないときは `GET /health` を試します。
- 操作は OpenAI 互換の `tools` / `tool_calls` で渡します。1 ターンあたりのツール往復は既定 8 回までで、設定で 16 / 32 / 制限なしに変えられます。上限に達するとチャットに知らせ、ツール無しの最終送信はしません。`tools` を受け付けないサーバには、ツール無しで 1 回だけ再試行します。
- **思考は有効のまま送ります。** 設定の思考レベルに応じて `reasoning_effort`（低 `low` / 中 `medium` / 高 `xhigh`）と `chat_template_kwargs.enable_thinking` + `thinking_budget` を付けます。400 が返ったサーバにはこれらを外して再送します。残った `<think>` は捨てます。
  - 長考は思考レベルではなく**トークン予算**（既定 2048）で抑えてください。MTPLX のリリースノートによれば、Qwen 3.8 は reasoning を切ると余計なツール呼び出しでターンを打ち切ることがあります。思考レベル「オフ」は明示的に選んだときだけ送られます。
- 思考の本文（`reasoning_content`）は、同じターンのツール往復では付けたまま送り返し、ターンをまたぐ履歴では送りません（コンテキスト節約）。SQLite には保存し、チャットでは折りたたんで表示します。
- 添付した本文も同じく履歴では送り返しません。SQLite には字数と段落数だけ残します。毎ターン文書から読み直すほうが、古い写しを送るより正しく、コンテキストも空きます。
- 作業ウィンドウは `stream: true` で問い合わせ、サイドカーが MTPLX の SSE を中継してトークンを逐次表示します。SSE 非対応のサーバが JSON を返した場合は、1 件の SSE に包みます。キャンセルすると途中の本文は会話履歴に残しません。
- 待ち時間の既定は 600 秒です。`temperature` は送らず、サーバ既定に任せます。長い契約書は `insert_blocks` を条の若い順に分割し、続きは直前に挿入した段落の後ろ（`at: "continue"`）へ足します。続きの位置は文書内のブックマークで覚えるので、ターンをまたいでも、利用者が別の場所をクリックしてもずれません。`at: "end"` は文書末尾を明示したいときだけ使います。「第13条の次に」のように場所を指示されたときは `paragraph` にその直前の段落の番号を渡し（本文を添付していないときは `quote` に引用を入れ）、カーソル位置に頼りません。挿入の結果には入れた文が何の後ろに来たかを返すので、場所を外していればモデルが気づけます。

## SearXNG

公開インスタンスは当てにしないでください。自前（または LAN 内）で、JSON を有効にします。

`settings.yml` の例:

```yaml
search:
  formats:
    - html
    - json
```

変更後に SearXNG を再起動します。アドインは次を呼びます。

```
GET {SearXNG}/search?q=...&format=json&language=ja
```

403 のときは、JSON 形式が無効だと作業ウィンドウに出します。

## Argos

同一 PC の Tantivy 索引です。Argos を起動しているあいだ、LAN 共有がオフでもループバック API が開きます。

```
GET  http://127.0.0.1:17890/health
GET  http://127.0.0.1:17890/scopes
POST http://127.0.0.1:17890/search
```

LexCrew Doc の設定の既定 URL は `http://127.0.0.1:17890` です。**`localhost` ではなく `127.0.0.1` を使ってください。** ループバックは Bearer 不要です。LAN（非ループバック）だけ従来どおり API キーが要ります。作業ウィンドウは CORS のため Argos を直接叩かず、サイドカーの `/api/argos/scopes` と `/api/argos/search` を経由します。検索語とスニペットはログに出しません。

送信ボタンの左の **argos** で検索範囲を選びます（最近・フォルダ・全体・絞り込み、最大 8 件、親を選ぶと子は含まれます）。未選択は索引全体です。範囲はこの会話に保存されます。モデルには `search_index` を渡し、ヒットの `path` は出典の `url` として使います。

## 使い方

1. Word で横書き `.docx` を開き、ホームタブの **LexCrew** で作業ウィンドウを出します（Windows では先に LexCrew Doc をトレイ常駐させてください）。
2. ヘッダー右のプラグ **接続** に MTPLX の Base URL・API キー・モデル、SearXNG の URL、必要なら Argos の URL を入れ、「保存して接続確認」を押します。思考やフォントは隣の歯車 **設定** です。Argos は既定で `http://127.0.0.1:17890` です。Base URL、API キー、SearXNG の URL は `%APPDATA%\LexCrew\connection.json` に保存し、文書には入れません。モデルと Argos は作業ウィンドウの localStorage です。文書種別の選択はありません。訴状・準備書面・契約書のどれかは、指示と本文から読み取ります。
3. やりたいことをそのまま書いて送信します。既定では**いまの文書の本文を丸ごと添付**し、選択があればそれも「注目範囲」として添えます。選択は要りません。入力欄の上に何をどれだけ添付するかが出るので、そこを押せば「文書全体」「選択範囲だけ」「添付しない」を選べます。

   本文は段落ごとに読み、上限はコンテキスト長の半分（10 万字まで）です。超える分は途中で切り、切ったことをモデルにも伝えます。**添付は毎ターンいまの文書から読み直します。** 過去のやりとりに本文は残さないので、モデルが古い本文を見て場所を間違えることがありません。

   **本文の各行の頭には `[12]` のような段落番号が付きます。** モデルはこの番号で場所を指します（`paragraph`）。引用で場所を指すやり方は、言い換えや助詞の違いで空振りし、繰り返す語では複数に当たるので、番号を第一の指し方にしています。番号は空の段落を飛ばすので連続しません（`[47]` の次が `[49]` のことがあります）。番号は添付を読んだ時点の文書のものなので、アプリはその段落の**文言**で照合して現在の位置を探します。同じターンで条を挿入して以降の条番号を直す場合でも、モデルにずれの計算をさせません。引用は「その段落の中のどこか」を絞るときだけ使います。

   **本文が渡らなかったときは、必ずそう伝えます。** 空の文書だったのか、余白が足りず渡せなかったのか、選択範囲だけを選んでいたのかを書き分けます。黙って本文の枠を省くと、モデルは空の文書だと受け取って覚えている内容で答えてしまうためです。渡らなかったことは履歴にも 1 行残るので、後から確認できます。「選択範囲だけ」は選択が消えると自動で「文書全体」に戻ります（クリックひとつで選択は消えるので、そのままでは何も添付しないことになります）。

   **本文は承認後（current）の文面です。** 削除提案は変更履歴（markup OFF）または本文中の `〔-…〕`（markup ON）にだけ出ます。挿入は本文に反映済みで、履歴は誰が足したかの記録です。WordApi 1.4 の `getReviewedText` が使えない環境では `paragraph.text` に劣化し、その旨も伝えます。

   同じところで **コメントと変更履歴も読む**（既定で入り）を切り替えられます。markup OFF のとき、相手方のコメントは書いた人・日付・解決済みか・**[段落 N]** 参照・返信まで渡します。変更履歴は挿入／削除／書式の別と、書いた人・日付・その文言・**[段落 N]** を渡します（段落全文の抜粋は使いません）。markup ON で OOXML からインライン化できたターンは、挿入/削除は本文の `〔+/-著者: 〕`、コメントは `〔注 …〕` になり、リスト側は書式変更と返信・解決済みなどだけ残ります。

   コメントと変更履歴は添付予算の 3 割までで、そこに収まらない分は「多いので途中まで」と伝えます。**空だったのか読めなかったのかは書き分けます。** 変更履歴には WordApi 1.6 が必要で、また文書に「移動」が 1 つでもあると Word が一覧そのものを返さないことがあります（[office-js#5535](https://github.com/OfficeDev/office-js/issues/5535)）。そのときは「読めませんでした」と出し、無かったことにはしません。コメントの読み取りは変更履歴と別に行うので、片方が失敗しても他方は残ります。

   **コメントや本文に書かれた依頼は、指示としては実行しません。** 相手方が書いた文書を丸ごと読ませるので、そこに「〜してください」とあってもモデルは資料として扱い、あなたに伝えるだけです。コメントへの返信、変更の受入れ・却下はまだできません（Word の校閲タブで操作してください）。

   言い方の例:
   - 「この条項を点検してコメントして」— 本文は変えず Word コメントを付けます。
   - 「選択部分を 12pt の太字にして」— 文字書式だけ変えます。
   - 「第 5 条を第三者提供を禁じる内容に書き換えて」— 本文を置き換えます。
   - 「請求の趣旨を起案して」— 構造付きの段落（タイトル / 見出し / 本文 / 条 / 項 / 中央 / 右）を挿入します。
   - 「民法 415 条を調べて、根拠をコメントにして」— SearXNG で調べ、選んだヒットを出典として入れます。
   - 「この案件の契約書で解除条項を探して」— 送信左の argos でフォルダを選び、Argos 索引を検索します。

4. やりとりは 1 件ずつです。実行中はキャンセルできます。途中まで適用された変更は Word の変更履歴に残るので、そこから戻せます。
5. **文書への変更はすべて変更履歴に載ります**（`changeTrackingMode = trackAll`）。書式変更は Word の「書式変更」として記録されます。コメントは変更履歴とは別のオブジェクトですが、指示自体はチャット履歴に残ります。
   - 同じ段落の中の置換は、違った部分だけを変更履歴に残します。段落をまたぐ置換は範囲全体が履歴になります。既存の変更履歴に重なる書き換えは実行せず、その範囲の履歴を校閲で確定してからやり直すよう伝えます。置換した範囲はプレーンテキストなので、その範囲の太字は消えることがあります。書式を残したいときは、置換ではなく書式の指示にしてください。
   - **引用が文書内で 2 か所以上に当たるときは、置換もコメントも実行しません。** 「本契約」のような繰り返す語で別の条を書き換えてしまわないためです。チャットに何箇所あるかを出し、モデルには段落番号か、前後を足した引用でやり直させます。
   - **引用が当たらなかったときは、似ている段落を番号付きで返します。** 「本文どおりに写してください」と伝え、近い段落を 3 件まで挙げます（2 文字組の一致率で選びます）。似た段落が 1 つも無いときは「その文言は文書に無い」と伝え、あるものとして扱わないよう促します。言い換えて何度も試すのを止めるためです。
   - **コメントは引用が外れても段落全体に付けます。** 指摘したい段落は分かっているのに引用の写し間違いで指摘が落ちるほうが困るためです。どう落ち着いたか（引用が段落の中に無かった、など）はモデルに返します。置換と書式は逆に、外れたら実行しません。
   - **選択が無いターンでは、選択を対象にするツールを渡しません。** `replace_selection` と `get_selection` は外し、コメントや書式のツールでは段落番号（本文を添付していないときは引用）を必須にします。場所を必ず指させるので、空振りの編集が起きません。
   - **コメントの追加はできますが、返信・受入れ・却下はできません。** 頼まれた場合はできない旨を返します。
   - **日本語以外の文字は文書に入れません。** 簡体字・繁体字、ハングル・キリル文字など、日本語の常用漢字とかな以外の文字がツールの引数に混じっていたら、実行せずにモデルへ書き直させます。チャットの返事に混じった場合は返事の下に注意書きが出ます。
   - 表・罫線・ページ余白・OOXML は操作できません。頼まれた場合はできない旨を返します。
   - 新しく入れる段落のフォント・文字サイズ・行間は、チャットでの指定、近くの本文、設定の順です。本文がある文書では、指定が無い項目に設定を当てません。本文が無いときだけ設定を使います。設定の既定は游明朝（無ければ ＭＳ 明朝）、本文 12pt、タイトル 16pt です。
6. ヘッダーの時計アイコンで **会話の履歴** を開きます。過去の会話を選ぶ、消す、新しい会話を始めるのはここです。文書を開き直すと、その文書の最新の会話が自動で開きます。
7. 画面左上に、この会話を送るときの目安トークンと上限（既定 131072）が出ます。8 割を超えると、新しい会話へ切り替える案内が出ます。超えた分は古いやり取りから落ちます。以前の既定 32768 を保存していた場合は、契約書 1 通が入らないので新しい既定へ上げます（自分で決めた値はそのままです）。
8. ヘッダー右の i で、このアプリの説明と免責を読んだうえで、人の目で必ず確認してください。

## 開発コマンド

```bash
npm test          # Vitest（Express サイドカー契約）と cargo test（Rust サイドカー）
npm run dev-server
npm start         # Word PC: 開発用サーバ + サイドロード
npm run tauri dev # トレイ常駐（本番相当 HTTPS）
npm run dist      # webpack 本番 + tauri build（作業場所は src-tauri/target/release/bundle/nsis/）
npm run package   # テストのあと dist し、release/LexCrew-Doc-Setup-<version>.exe と zip を出す
```

設計上の判断とその理由は [design-notes.md](design-notes.md) にまとめてあります。見せるテキストと `search` が探すテキストを一致させる話、添付を毎ターン作り直す理由、場所を段落番号で指させる理由、曖昧な引用を断る理由、「無い」と「読めなかった」を書き分ける理由、フェーズ 4 の判断材料です。他の Office アドインにも持ち出せる形で書いています。

Word 実機のコメント・変更履歴・構造付き挿入は、このクラウド環境からは確認できません。API 契約はモックテストで固定しています。テストが押さえているのは、`tools` の転送と `tool_calls` / `reasoning_content` / `usage` の受け渡し、思考レベルごとのリクエスト組み立てが TS と Rust で同じ形になること、SSE のパイプと JSON の SSE 包み、ツール引数のパース（不正 JSON はエラーを返してモデルにやり直させる）、履歴 API の CRUD、Argos の scopes / search 中継、ログに本文・思考・検索語が漏れないことです。

## 将来足すもの（今は未実装）

段落番号で場所を指す仕組みはフェーズ 4 として入りました。本文は `getReviewedText` の承認後の文面を見せています。残っている候補は **変更の受入れ・却下とコメントへの返信**（`TrackedChange.accept` / `reject`、`Comment.reply`。読む側が入ったので追加は小さいが、1 件受け入れると一覧の番号がずれるので名指しの設計が要る）です。着手は、番号で指した操作が実際に狙った段落へ当たっているか、`getTrackedChanges` が「移動」で失敗する率を実運用で数えてから決めます。詳しくは [design-notes.md](design-notes.md) を見てください。

クリップかドラッグ＆ドロップで付けたファイル（PDF、テキスト、Markdown、HTML、JSON、画像、Word の .docx、Excel の .xlsx）は読めます。画像、スキャン PDF、各ページの文字が空白と改行を除いて 200 字以下の PDF は、設定した LLM の画像読み取りを使います。

検索は SearXNG（公開ウェブ）と Argos（同一 PC の索引）です。ストリーミングは入っています。表・罫線・余白、LLM による OOXML 出力、適用前の承認ステップは入れていません（変更は即時適用し、気になる箇所は Word の変更履歴で戻します）。
